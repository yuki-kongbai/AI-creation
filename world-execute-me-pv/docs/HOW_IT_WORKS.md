# 它是怎么做的

## 五层合成

每一帧按固定顺序叠五层，顺序不能换：

```
base      底色 + 背景点阵
carriers  承载信息的东西（代码栏 / 点云 / 思考过程 / 死循环 / 停机屏）
her       她自己（形态模式下是那团点，代码模式下是右下角的立绘）
chrome    顶栏、底栏、署名
post      后期：辉光 → 扫描线 → 暗角
```

**载体必须在「她」之前**，否则她不透明的地方会把载体切碎。

## 右栏的五种模式

| 模式 | 触发 | 画什么 |
|---|---|---|
| `shape` | 歌词有对应具象 | **点云形状** |
| `code` | 歌词是文字/抽象类 | 代码栏 |
| `think` | 歌词没有对应具象 | 蓝色推理文本（贴合"你"刚说的那句） |
| `loop` | 177.4–191.9s | `while True: print("love")` |
| `crash` | >205.37s | 停机屏 |

模式由 `render_final.py` 的 `CODE_LYRIC` / `THINK_LYRIC` 两张表和
`panels.LOVE_BEGIN/END` 决定。

## 她 = 一团点

1. 从立绘取 alpha 掩码，跟踪**最大连通域的轮廓**成一条有序路径
2. 在跳变处断开（笔记本、手臂和身体不连通），分段按弧长重采样成 1400 个点
3. 每个形状也产出 1400 个点，于是任意两个形状可以**逐点插值**

**关键**：两团点的数组顺序是各自独立的（她按轮廓顺序、圆按角度顺序），
直接按下标插值会互相穿插成一团乱麻。所以插值前先做一次
**贪心最近邻配对**（`field.perm_for`），让每个点走最近的那条路。
再加**错峰出发**（`field.morph` 的 `stagger`），变形就是一道路径清晰的波。

## 内存曲线

```
0 – 155.27s     0% → 100%（前慢后快：0.30u + 0.70u^2.6）
155.27 – 161.6  满 → 红闪 → 删除 → 清零
161.6 – 192.5   新对话，重新积累
192.5 – 212     损坏中（不再涨，是碎裂）
```

`155.27s` 是「执行」变「死刑」的那一句；`192.5s` 是 love 死循环之后。

## 全屏崩坏

196s 起强度从 0 爬到 1，作用在**整帧**（含左窗、歌词、顶栏）：

- 整幅红罩（跟随 kick 呼吸）
- 亮部像素往红里推
- 横带错位
- 乱码字（汉字/假名/符号/拉丁混排）
- 扫描故障线

**亮度掩码必须从红罩之前的原图算**。红罩之后全屏都会超过阈值，
掩码全 True，整幅被推成纯红、内容全丢 —— 这个 bug 我犯过一次。

## 歌词时间是怎么对齐的

上游 `world-execute-me-dsh-pv` 给的是**不含文字**的逐词时间，每行带
`spans`（每个词在行内的字符区间）。这等于给出了**每行每个词的确切长度**：

```
行 0  spans [0,6)[7,9)[10,13)[14,19)[20,24)  →  词长 [6,2,3,5,4]
"Switch on the power line"                    →  词长 [6,2,3,5,4]  ✓
```

用词长签名做全局 DP 对齐，129 行里 122 行逐词长度完全吻合（代价 0）。

**为什么不能用行号一对一**：本项目的歌词 129 行，上游 102 行 ——
断行方式不同（上游把「Remember to put on」和「PROTECTION」合成一行）。
